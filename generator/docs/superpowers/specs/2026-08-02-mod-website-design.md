# Enhanced Creatures mod website

## Goal

Give the mod a small, standalone website served from `docs/` (GitHub Pages root)
with a D&D/Baldur's Gate-flavored look. Three pages: a landing page, the
already-generated monster compendium (re-themed), and a new changelog page.
Not affiliated with Gibberlings3 — `stratagems/doc/readme-stratagems.html` was
used only as a structural reference (ribbon nav / table of contents idea), no
G3 branding, assets, or CSS is reused.

## Site structure

```
docs/
  index.html          # hand-authored landing page
  monsters.html        # generated by documentationService (existing), re-themed
  changelog.html        # generated by new changelogService, from root CHANGELOG.md
  monsters.css          # hand-authored companion to monsters.html (new — currently missing)
  monsters.js            # hand-authored companion to monsters.html (new — currently missing)
  assets/
    site.css            # shared theme: palette, fonts, nav bar, card/panel primitives
CHANGELOG.md            # new, Keep-a-Changelog format, source of truth for changelog.html
```

`docs/monsters.html`, `docs/monsters.css`, `docs/monsters.js`, and
`docs/changelog.html` are build outputs (checked in, like `docs/monsters.html`
already is) — they're regenerated by `npm run <generate script>` in
`generator/`, not edited by hand. `docs/index.html` and `docs/assets/site.css`
are hand-authored and never touched by the generator.

## Theme

Chosen direction: **Illuminated Manuscript**, textured decoration level.

- Background: parchment (`#f2e4c2`) with a subtle two-layer radial-gradient
  dot texture (validated in the brainstorming mockup) for a paper-grain feel.
- Text: ink brown (`#3b2a17`).
- Panels/cards: `#e8d6ac` background, `1px solid #b8860b` (dark goldenrod) border.
- Headings/nav/accents: deep red (`#8b1a1a`) for titles and active nav state,
  gold (`#b8860b`) for rule lines and borders.
- Nav bar background: `#e3cd9a`, with a `2px solid #8b1a1a` bottom border.
- Fonts: **Cinzel** for headings, site title, and nav (engraved-capital,
  D&D-branding-adjacent look); **Lora** for body text (warm, book-like serif).
  Both loaded via a Google Fonts `<link>` tag (CDN, no vendoring).
- These values become CSS custom properties in `docs/assets/site.css` so
  `monsters.css` reads the same palette instead of duplicating literals.

### Shared top nav

Every page gets the same nav bar: `⚔ Enhanced Creatures` (links to
`index.html`) on the left, `Home · Monsters · Changelog` links on the right,
with a gold/red active-page indicator. Since these are static files with no
templating include mechanism between `index.html` and the generator's
templates, the nav markup is duplicated in three places:
`docs/index.html`, `generator/lib/templates/index.html` (used by
`documentationService`), and the new changelog template. This is an accepted
duplication — the site is 3 pages, keeping the nav in sync by hand is cheap.

## Page: `docs/index.html`

Sections, in order:
1. Hero — title "A Monstrous Compendium, Reforged" + one-line tagline.
2. About — paraphrased from `README.md`: brings monsters closer to P&P
   (2e/3e mix), brief history (2005–2011 attempt, restarted 2025 from an
   aTweaks base, heavily refactored), TypeScript-driven generator.
3. Install Order — install late, especially after SCS.
4. Compatibility — don't use "Use BG Walking Speeds" from The Tweaks Anthology.
5. Credits — aVENGER (aTweaks), Wisp (current aTweaks maintainer), modding
   community.
6. License — CC BY-NC-SA 3.0, with link.
7. Two link-cards to Monsters and Changelog pages.
8. Footer — license line + GitHub repo link.

No explicit "not affiliated with Gibberlings3" disclaimer text is added —
the constraint is met by not using any G3 branding/assets, consistent with
how the README already credits aVENGER/Wisp for the aTweaks basis without
implying G3 affiliation.

## Page: `docs/monsters.html` (re-theme, not re-architect)

Existing generation logic (`documentationService`, `lib/templates/index.html`,
`lib/templates/monster.html`) is unchanged structurally — same sidebar family
tree, stat-grid, traits, abilities, spellbook tabs. Changes:
- Add the shared top nav markup to `lib/templates/index.html`, and a
  `<link>` to `../assets/site.css` alongside the existing `monsters.css` link.
- Write `docs/monsters.css` from scratch (it's referenced by the template but
  doesn't exist on disk today) in the new palette: sidebar family list,
  `.stat-grid` cards, `.detail-section`, `.ability-entry`, spellbook tab
  buttons/panels, responsive collapse of the sidebar behind the existing
  `.menu-toggle` hamburger button/backdrop for narrow viewports.
- Write `docs/monsters.js` from scratch: hamburger toggle open/close and the
  spellbook tab-button/tab-panel switching (`data-tab` wiring implied by
  `documentation.service.ts`'s existing `spellbook-tab-button` /
  `spellbook-tab-panel` markup).
- After template/CSS/JS changes, regenerate `docs/monsters.html` via the
  generator so the committed file matches what `pipeline.golden.test.ts`
  expects (that test diffs the generator's output against what's on disk).

## Page: `docs/changelog.html` (new)

- New root `CHANGELOG.md`, Keep-a-Changelog format:
  ```markdown
  # Changelog

  ## [Unreleased]

  ### Added
  - ...
  ```
  Seeded with just the `[Unreleased]` scaffold — no fabricated history — ready
  for entries to be added going forward.
- New `changelogService` in `generator/lib/src/services/doc/`, mirroring
  `documentationService`'s read-template/replace-tokens/write-file pattern:
  reads `CHANGELOG.md` from `State.modFolder` (the repo root — same
  `path.join(State.modFolder, ...)` convention `utils.writeFile` already uses,
  so the golden test's temp-dir redirection works for it too), converts
  Markdown to HTML using **`marked`** (new dependency — small,
  zero-dependency, well-tested; avoids hand-rolling Markdown parsing for
  content that will grow bold text/links/nested lists over time), and injects
  the resulting HTML into a new `generator/lib/templates/changelog.html`
  template (same nav/theme shell as the monsters page) before writing
  `docs/changelog.html`.
- Hooked into the pipeline the same way `documentationService.generate()` is
  called today (from `mainService`/`index.ts`), so one generation run
  produces both `docs/monsters.html` and `docs/changelog.html`.
- `marked` is added as a `generator` dependency (build-time use only, not
  shipped to the browser — `docs/changelog.html` is static output).

## Testing

- `generator`: unit test for `changelogService` (template token replacement,
  Markdown → HTML conversion) following the existing pattern in
  `documentation.service.test.ts`.
- Regenerate docs output and confirm `pipeline.golden.test.ts` passes. That
  test's `beforeAll` only copies `lib/pnp-monster` into its temp `modFolder`
  before running the pipeline, so it also needs to copy `CHANGELOG.md` in
  (same pattern) or `changelogService` will fail to find it there; and its
  `FIXED_GENERATED_FILES` list needs `docs/changelog.html` added.
- Manual check: open `docs/index.html`, `docs/monsters.html`, and
  `docs/changelog.html` in a browser at both desktop and narrow/mobile widths
  to confirm the shared theme, nav, and responsive behavior look right.

## Out of scope

- No dark mode / theme toggle.
- No search or filtering on the monsters page beyond what exists today.
- No GitHub Pages CI/workflow setup — enabling Pages on `docs/` in repo
  settings is a separate, manual step for the user.
- No changes to the WeiDU/BAF generation logic — only the documentation
  templates, new CSS/JS, and the new changelog step.
